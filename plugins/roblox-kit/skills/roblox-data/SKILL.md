# Данные в Roblox

## Профиль игрока
- Один ключ на игрока: `"Player_" .. player.UserId`, таблица с полем `version` для миграций.
- Загрузка при `PlayerAdded` с ретраями (экспоненциальная пауза, 3–5 попыток); при неудаче — **не давать играть с пустым профилем поверх реального** (кик с сообщением или режим без сохранения).
- Запись: `UpdateAsync` (не `SetAsync`) — видит текущее значение, нет гонок. Автосохранение раз в 1–3 минуты, при `PlayerRemoving` и в `game:BindToClose` (успеть за ~30 с).
- **Сессионная блокировка:** в профиле — ID сервера и время; другой сервер не пишет, пока блокировка свежая. Это защищает от дюпа при перезаходе. Готовые библиотеки (ProfileStore) — только через `skill-vetting`, иначе свой минимальный аналог.
- Бюджеты запросов: `DataStoreService:GetRequestBudgetForRequestType`; не писать в цикле по каждому событию — копить изменения в памяти.
- Лимит значения ~4 МБ на ключ; храни ID и числа, не объекты.
- Валидация при загрузке: отсутствующие поля → значения по умолчанию, неизвестные — игнорировать, типы проверять.

## Общие данные
- **OrderedDataStore** — лидерборды (`GetSortedAsync`), обновлять не чаще раза в минуту на игрока.
- **MemoryStoreService** — временные очереди и карты (матчмейкинг, лобби, ивенты), с TTL.
- **MessagingService** — сообщения между серверами (глобальные анонсы, старт ивента).

## Тестирование
- В Studio: Game Settings → Security → Enable Studio Access to API Services; для тестов — отдельный DataStore с префиксом `Test_`.
- Проверь сценарии: выход во время сохранения, быстрый перезаход на другой сервер, отключение API (ретраи), битые/старые профили.
