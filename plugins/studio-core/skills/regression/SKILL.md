# Регрессия

Команды — в `CLAUDE.md`, раздел «Студия». Как писать тесты на конкретном движке — скилл движка (`godot-testing`, `roblox-mcp`).

## 1. Прогон (по порядку, стоп на первом провале)
1. Юнит-тесты (секунды) — ждём 0 упавших и код выхода 0.
2. Автотест/сценарный плейтест — нет ошибок скриптов, сценарий дошёл до конца.
3. Если менялось влияющее на нагрузку (враги, эффекты, спавн, сеть) — нагрузочный прогон; сравни с прошлым результатом.
4. Мультиплеер — прогон с несколькими клиентами, если затронута сеть.

## 2. Тесты
- Тестируй логику и данные отдельно от сцен: таблицы, формулы, выбор наград, экономику, валидацию сетевых сообщений.
- **Каждый исправленный баг = новый тест**, который падал бы до фикса; имя упоминает баг (`test_bug_007_...`).
- Сторонние тестовые фреймворки — только через `skill-vetting`; свой минимальный раннер предпочтительнее.

## 3. Реестр
`docs/qa/regression.md`: `| Область | Тест | Что защищает | Добавлен (дата/баг) |` + раздел «Известные пробелы» (что только руками).

## 4. Отчёт
`Юнит: N/N ✅ | Автотест: ✅ | Нагрузка: … | Новые тесты: … | Не покрыто: …`
