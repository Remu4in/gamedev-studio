# Тесты в Godot

## Юнит-тесты (свой раннер, без GUT/gdUnit4)
1. Скопируй шаблоны из `templates/` рядом с этим файлом в `res://tests/`: `test_case.gd` (базовый класс: `check`, `check_eq`, `check_near`) и `run_tests.gd` (находит `tests/test_*.gd`, вызывает `test_*`, код выхода 1 при падениях).
2. Запуск: `<godot_console> --headless --path . --script res://tests/run_tests.gd` → `ИТОГО: N тестов, упало M`.
3. Тест: `tests/test_<область>.gd`, `extends "res://tests/test_case.gd"`, методы `test_*`, сообщения по-русски.
4. Тестируй таблицы данных (обязательные поля, ресурсы существуют), формулы (кривые опыта, сложности), выбор наград, применение улучшений. Для объектов с `_ready()` — заглушки (`class FakePlayer extends RefCounted` с нужными полями).
5. Проверь раннер один раз намеренно падающим тестом.

## Сценарный автотест (бот)
- Флаги командной строки через `OS.get_cmdline_user_args()` после `--`: `--autotest` (бот играет сам), `--god` (бессмертие), `--bench`/`--bench-late` (нагрузка), `--screenshot=<файл> --shot-at=<сек>`.
- Бот: простая логика движения (кайтинг от толпы, сбор наград), автоматический выбор улучшений, ускорение времени `Engine.time_scale`.
- Отчёт в консоль каждые N секунд: время, уровень, HP, число врагов, avg/max кадра; итог — `ПОБЕДА`/`СМЕРТЬ`/`конец по времени`; `quit()` с кодом.
- Скриншоты для арт-проверки — с реальным рендером (`--rendering-driver opengl3`), не headless.

## Правила
- Любой `SCRIPT ERROR`/`ERROR` в выводе — провал.
- Флаги автотеста и читов не должны работать в релизном билде (проверка `OS.is_debug_build()` или фича-тег экспорта).
