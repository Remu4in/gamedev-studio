# Godot 4 / GDScript

## Код
- Статическая типизация везде (`var hp: int`, `-> void`); если тип не выводится (`:=` от Variant) — укажи явно.
- Не затеняй встроенные имена (`sign`, `len`, `name`, `position`) — это предупреждения, которые прячут баги.
- Данные (враги, оружие, награды) — таблицами в отдельных скриптах/ресурсах; логика читает таблицы. Новый контент = новая запись, не новый код.
- Связь между системами — сигналы и autoload-синглтоны для глобального состояния; без поиска нод по длинным путям.
- `material_override` на `MeshInstance3D`, а не `material`.
- Все «магические числа» эффектов и баланса — константы в одном месте.

## Производительность (выучено на bullet heaven с 200+ врагами)
- **Никаких физических коллизий враг–враг.** Разведение толпы — своя пространственная сетка (spatial hash) с лимитом проверок на врага (~10).
- **Пулы** для врагов, снарядов, частиц, цифр урона: `activate()` / `deactivate()` вместо `instantiate()`/`queue_free()` в бою.
- **Очередь спавна:** не больше N созданий за тик (2–4), чтобы не было скачков кадра.
- **Предзагрузка** моделей и сцен при старте уровня.
- **AnimationPlayer:** не переписывай свойства анимации (`loop_mode` и т. п.) каждый раз — только если значение отличается: запись в общую анимацию перестраивает кэш у всех плееров, которые её используют, и даёт фризы.
- Статичное окружение — `MultiMeshInstance3D`, простые коллизии (боксы).
- Поиск ближайших врагов — через сетку, не перебором группы в цикле.
- Замер: свой бенчмарк-режим (средний и максимальный кадр), норма — avg < 16 мс на целевом железе.

## Game feel (рецепты к скиллу `game-feel`)
- Тряска: поле `trauma` в риге камеры, затухание ~1.5/с, `h_offset/v_offset = trauma² × амплитуда × FastNoiseLite(t)`.
- Hitstop: `Engine.time_scale = 0.05` на 0.04–0.08 с через `get_tree().create_timer(t, true, false, true)` (ignore_time_scale).
- Частицы смерти: `GPUParticles3D` one_shot, 8–16 частиц, без теней, из пула.
- Звук: `AudioStreamRandomizer` для вариаций pitch, `max_polyphony` у плееров.

## godot-mcp
- Запуск проекта и чтение вывода — инструменты MCP (`run_project`, `get_debug_output`); headless-команды из `CLAUDE.md` — для автотестов.
- После правок `.tscn`/ассетов — импорт `--headless --path . --import`.
- Любой `SCRIPT ERROR` в выводе — исправить до продолжения.
