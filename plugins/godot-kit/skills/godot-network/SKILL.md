# Сеть в Godot 4

Общие принципы — у агента `network-programmer`. Здесь — как это делается в Godot.

## Основа
- `ENetMultiplayerPeer` (LAN/прямое подключение) или Steam (GodotSteam: лобби, P2P через relay — без проброса портов; аддон только через `skill-vetting`).
- `multiplayer.is_server()`, `multiplayer.get_unique_id()`, сигналы `peer_connected/peer_disconnected`.
- **Кооп в bullet heaven:** хост авторитетен для врагов, урона, наград; клиенты шлют ввод/намерения.

## RPC
- `@rpc("any_peer", "call_remote", "reliable")` — только для запросов клиента к серверу; на сервере **всегда** проверяй `multiplayer.get_remote_sender_id()`, права, диапазоны, кулдауны.
- `@rpc("authority", ...)` — события от сервера клиентам.
- `unreliable`/`unreliable_ordered` — частые обновления позиций; `reliable` — важные события (смерть, награда, покупка).
- Не передавай объекты и ресурсы — только простые типы и ID.

## Репликация
- `MultiplayerSpawner` для появления врагов/снарядов у всех; `MultiplayerSynchronizer` с минимальным набором свойств и интервалом.
- Сотни врагов: не синхронизируй каждого синхронизатором — шли пакетами (массив позиций/ID с частотой 10–20 Гц) и интерполируй на клиенте; снаряды — детерминированно от seed и времени выстрела.
- Эффекты, цифры урона, звуки — только локально по событиям.

## Тестирование
- Несколько экземпляров: Debug → Customize Run Instances (2–4), или несколько процессов из командной строки с флагами `--host`/`--join`.
- Искусственный лаг/потери — средствами ОС или прокси; крайние случаи: вход посреди раунда, выход хоста, одновременный подбор награды.
